# claude-ssh-wrapper

Тонкий враппер над `claude` CLI (Claude Code), который заворачивает его сетевой трафик в SSH-тоннель до пользовательского сервера с HTTP-прокси.

## Что это и зачем

На macOS нет per-process routing (нет network namespaces как в Linux). Настоящий per-process VPN без контейнера/VM невозможен. Но можно добиться эквивалентного результата через **HTTP-прокси + env-переменную**: `claude` (Node-приложение) уважает `HTTPS_PROXY`, так что достаточно поднять прокси на удалённом сервере, пробросить его SSH-тоннелем на `localhost`, выставить env — и трафик `claude` идёт через сервер, а остальная система — мимо.

Враппер всё это автоматизирует: читает конфиг, поднимает SSH ControlMaster (один раз на сессию), выставляет env, вызывает настоящий бинарь `claude`.

## Неизменные архитектурные решения

- **Не VPN в сетевом смысле.** Это SSH + HTTP-прокси. WireGuard/OpenVPN сюда не затаскиваем — перестанет быть «тонкой обёрткой».
- **Враппер живёт в `~/bin/claude`**, настоящий бинарь не переименовывается. Враппер вызывает его по абсолютному пути. Это переживает обновления `claude` через `npm`/installer.
- **Конфиг в `~/.claude-wrapper/config.json`**. Единственный источник правды: где сервер, какие порты, где настоящий `claude`.
- **SSH ControlMaster.** Первый запуск поднимает master-соединение в фоне, последующие переиспользуют сокет — старт `claude` не тормозится рукопожатием SSH каждый раз.
- **Env-переменные, не хаки.** Только `HTTPS_PROXY`/`HTTP_PROXY`/`NO_PROXY`. Никакой магии с `DYLD_*`, `PF`, никаких network extensions.
- **Никакой авто-остановки туннеля.** Master живёт до явного `ssh -O exit` или перезагрузки. Reference-counting (гасить после последнего claude) — сознательно вне MVP.

## Структура репозитория

```
claude-ssh-wrapper/
├── CLAUDE.md               # этот файл
├── README.md               # пользовательский install/usage
├── bin/
│   └── claude              # сам враппер (bash)
├── install.sh              # установщик (интерактивный)
├── uninstall.sh            # деинсталлятор (--purge стирает и конфиг)
└── scripts/
    ├── bash-check.sh       # end-to-end проверка ключ/SSH/прокси с hardcoded дефолтами
    └── wrapper-check.sh    # то же, но через реальный ~/.claude-wrapper/config.json
```

## Технологический стек

- **Bash** для враппера и всех скриптов. Никаких Node/Python/Go в рантайме — слишком жирно для тонкой обёртки. Обязательны только `ssh` (на маке из коробки) и `jq` (installer проверяет, подсказывает `brew install jq`).
- **Сервер:** любой HTTP-прокси, слушающий только на `127.0.0.1` (доступ только через SSH-форвард). `tinyproxy` — базовый рекомендуемый вариант, но работает и `xray` HTTP inbound, и `3proxy`, и `squid` — выбор остаётся за деплойщиком.

## Что НЕ делаем

- Не оборачиваем `claude` в Docker-контейнер (слишком много трений с MCP, правами на файлы, SSH-ключами).
- Не поддерживаем Linux как первую платформу (там per-process routing делается через netns/WireGuard — кроссплатформенное решение получится хуже каждого из нативных). Скрипты, скорее всего, заработают, но mgmt-доки не пишем.
- Не храним креды SSH в конфиге. Используем стандартный `~/.ssh/config` + ключи.
- Не терминируем TLS на прокси — это `CONNECT`-тоннель, никакого MITM.

## Конвенции

- Скрипты `bash`, не `sh`. Shebang `#!/usr/bin/env bash`, в начале `set -euo pipefail`.
- Комментарии в коде — только про *почему*, не *что*. Имена переменных — самодокументируемые (`REMOTE_HOST`, не `h`).
- Пользовательские сообщения (echo в installer, ошибки) — на английском.
- Никаких deps-менеджеров, lock-файлов, CI — пока не требуется. Добавляется осознанно.
- Все bash-файлы должны проходить `bash -n` и `shellcheck` без замечаний.

## Работа с этим проектом

Когда добавляешь/меняешь код:
1. Инварианты из раздела «Неизменные архитектурные решения» не трогаем без отдельного обсуждения.
2. Меняешь поведение враппера — обнови релевантную секцию в этом файле и/или в `README.md`.
3. Добавляешь поле в конфиг — документируй в `README.md` (таблица полей) и учитывай в `bin/claude`.
4. Добавляешь новый скрипт — добавь в «Структура репозитория» выше.
